# M33 摔倒判断与手机短信投递链路

本文区分“开发板已经检测并告警”和“手机最终发送短信”。两者不是同一个成功条件。

## 完整链路

```text
M33 IMU 采样与判断
  └─ IMU_ALERT type=fall ...
      └─ OpenAMP/RPMsg → /dev/ttyRPMSG0
          └─ radar_fusion (A35)
              ├─ 本地动作：LED + 摔倒音频 + DVR 保存
              ├─ sensor_events.csv
              └─ UDP 127.0.0.1:8890
                  └─ HUD
                      ├─ imu_delivery.csv
                      └─ UDP 广播 192.168.152.255:8889
                          └─ 手机 App
                              └─ Android 短信接口
```

LED 闪烁只证明 A35 已进入本地告警状态。它不能证明 HUD 收到 UDP，也不能证明
手机 App 在线、拥有短信权限或最终发送成功。

## 当前 M33 判断逻辑

当前板上固件与工作区 M33 源码中的关键常量一致。IMU 原始重力基准为 `8192`。

### 摔倒

- 姿态数据必须有效，且数据年龄不超过 `500 ms`。
- `abs(roll) >= 6000` 或 `abs(pitch) >= 6000` 判定为倾倒姿态。
- 倾倒姿态连续保持 `2000 ms` 后上报 `type=fall reason=tilt_hold`。
- M33 各类 IMU 告警共享 `2000 ms` 的最小上报间隔。
- 源码还计算了合加速度 `12500` 和单轴冲击 `12000`，但当前摔倒最终条件
  **没有要求先发生冲击**。

因此，开发板安装角度不正确、车辆长时间大角度倾斜或姿态零点偏移，都可能在
没有真实摔倒时触发。冲击与倾倒的组合判定应在取得室外标注数据后再调整。

### 路面颠簸

候选条件包括：Z 轴变化 `>=1400`、合加速度变化 `>=1800`、
`abs(ay)>=2200` 或 `abs(gx/gy)>=2200`。3 秒窗口内至少 5 次命中，且持续
至少 1.5 秒后上报 `road_bump`。

当前静态开发板日志中约每 2 秒出现一次 `sustained_road_shock`，说明现有阈值
或安装基线尚不适用于当前姿态。Dashboard 会在最近 60 秒达到 5 次时提示标定警告。

### 急刹

以 Y 轴相对 IIR 基线的变化为主：`abs(y_delta)>=900`，需比 X 轴变化大 300，
同时限制 X/Z 干扰；强事件阈值为 `2200`，否则需在 1.5 秒内连续确认 2 次。

## 已定位的“LED 有、短信无”软件问题

旧 HUD 使用一个全局 60 秒冷却时间处理所有 IMU 事件。频繁的 `road_bump`
先占用冷却窗口后，窗口内的真实 `fall_down` 会被 HUD 直接丢弃；与此同时 A35
已经独立点亮 LED，所以出现“LED 闪烁但手机无短信”。

现已改为摔倒、急刹、颠簸分别冷却。同类事件仍保持 60 秒防刷屏，
`road_bump` 不再阻断 `fall_down`。只有 UDP 广播成功后才更新时间戳。

## 现在能确认到哪一步

`sensor_events.csv` 记录 M33 到达 A35 和 A35 发往 HUD；`imu_delivery.csv`
记录 HUD 接收、同类冷却和发往手机的 UDP 广播结果。Dashboard 的“最近一次
摔倒链路”按 `event_id` 显示各跳状态。

当前手机 App 源码不在此仓库，协议也没有 App 收包或 SMS 成功回执。因此最后一格
固定显示“手机 / SMS 未确认”。`sendto()` 成功只代表开发板把 UDP 数据交给网络栈，
不代表手机收到或短信发送成功。

下一步要实现端到端确认，需要手机在收到事件和短信 API 返回后，向开发板新增
ACK（包含同一个 `event_id`、接收状态、短信状态与错误码）。在此之前，排查手机端
还应确认 App 前台/后台存活、WiFi 广播接收、短信权限、默认 SIM 和系统省电限制。

## 无室外环境时的测试

1. 打开 Dashboard，确认 CAM/NPU 时间持续刷新。
2. 查看跨传感器时间线，确认 `imu_m33 → a35_hud → hud_delivery` 顺序完整。
3. 使用现有测试参数 `-t` 注入 A35 本地摔倒只能验证 LED/音频/DVR，不能代替
   M33 的真实 `IMU_ALERT`。
4. 用 UDP 构造带唯一 `event_id` 的 `fall_down` 消息发往 8890，可验证 HUD 分类
   冷却、8889 广播和 `imu_delivery.csv`，但仍不能证明手机短信成功。
5. 室外测试时，在网页先开始人工标签，完成事件后结束标签，再按 `timestamp_ms`
   联合分析雷达、NPU、IMU、投递记录和人工区间。
