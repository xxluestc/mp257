# 代码与维护约定

本约定用于自有应用代码的整理和后续修改。A35 保持 C/C++17 混合工程；WBA 保持现有 C、HAL 和 Keil 工程。代码规范通过小步修改和主机检查落实。

## 文件与命名

- 自有文件使用小写 `snake_case`，文件名表达职责；C 文件使用 `.c/.h`，当前 C++ 模块保持 `.cpp/.h`，C++ 专用头文件无需为了扩展名统一而改名。
- `camera`、`npu_detect`、`ble_risk_output`、`nav_tts` 等现有名称符合约定。后续拆分按职责命名，例如 `frame_pool`、`bounded_queue`、`dvr_ring`、`radar_parser`、`fusion_controller`。
- C 函数使用模块前缀和 `snake_case`；新 C++ 类型使用 `PascalCase`，函数与变量使用 `snake_case`，私有成员使用尾随下划线。兼容接口按实际调用关系迁移。
- 单位写进物理量名称，例如 `distance_m`、`timestamp_us`、`timeout_ms`、`capacity_bytes`。同一个时间戳必须记录时钟来源。
- 可执行文件名、systemd 服务名、运行路径、JSON 字段和无线协议字段属于外部接口；修改名称时同步检查编译、打包、部署、配置和文档引用。
- ST HAL/CMSIS/WPAN、STAI 头文件、cJSON 和 CubeMX 生成布局随上游维护。业务文件的格式检查范围由工具明确选择。

## 格式与检查

A35 自有 C/C++ 文件使用 clang-format **18.1.8**，4 空格缩进、100 列目标宽度和 LF。保留 include 次序与注释内容。项目内 `.clang-format` 是格式依据。

在 `apps/a35` 执行：

```bash
python3 -m pip install clang-format==18.1.8
python3 tools/check_format.py        # 检查，不修改
python3 tools/check_format.py --fix  # 应用格式
```

也可通过 `--clang-format /path/to/clang-format` 指定工具。Windows 使用可用的 `python` 命令。CI 执行同一格式检查、现有 Shell/Python 检查和 Dashboard 主机测试。

`.clang-tidy` 提供一组面向缺陷的检查规则，需在匹配目标工具链、sysroot 和编译数据库的 Linux 构建环境执行；当前 CI 不将其标记为已运行。处理检查结果后再逐步扩大规则范围，不对第三方源码统一开启 `-Werror`。

## 接口与资源

- 对外接口说明输入范围、返回值、资源所有权、线程要求和可能的阻塞行为。
- C++ 新模块用 RAII 管理 fd、映射、锁和内存；C 模块采用明确的初始化、失败清理和销毁流程。
- 检查分配、线程创建、读写和 `ioctl` 返回值；处理短读写、`EINTR` 与 `EAGAIN` 时明确重试条件和期限。
- 长度、索引、图像尺寸和容量在使用前检查，乘法和加法先检查溢出。
- C/C++ 共用接口使用 `extern "C"` 保护；C 头文件可单独包含。
- 配置在加载时完成类型、范围与组合校验。日志记录失败原因及错误码，不用“调用已发出”表示操作已经完成。

## 并发与退出

- 每个设备和可变状态都有明确所有者；其他线程通过消息或受保护的快照访问。
- `volatile` 不用于线程同步。单个独立标志可用原子变量，关联字段使用同一把锁或由单个线程更新。
- 线程队列必须有容量、满队列策略及关闭语义。等待使用带条件的 `condition_variable`，关闭时唤醒等待者。
- 不在共享锁内执行设备 I/O、推理、编码和文件同步。
- 业务持续时间使用单调时钟，日历时间仅用于展示。跨 M33/A35 的时钟不能直接相减。
- 退出时停止输入，关闭队列，完成有界清理并 join 工作线程，最后销毁帧池和设备资源。

## 修改与验证

- 格式修改独立提交；结构调整与其对应的构建、运行接入一起提交，便于审查与回退。
- 头文件或源文件改名时同步修改 include、构建规则和相关文档；保留第三方来源与许可证。
- 优先测试边界解析、资源释放、状态转换和并发生命周期，不用大量镜像实现的测试代替行为验证。
- 编译通过、主机测试通过、实机验证通过分别记录。本轮包括运行源码重构与主机检查，不包含板端部署、烧录、无线协议变更或硬件故障恢复验收。
