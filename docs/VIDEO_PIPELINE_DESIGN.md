# 视频流水线设计约定

状态：设计方案，尚未接入当前业务代码。当前运行链路见 [数据流文档](../mier/lyr/camera_detect/docs/DATA_FLOW.md)。本设计作为后续实现和讲解的共同依据，主机测试结果与板端验证结果分别记录。

## 执行与所有权

采用一个主业务进程：主线程负责融合状态机，Camera、Radar、NPU、DVR 分别承担独立工作角色。现有 RPMsg、音频等辅助任务根据其职责接入。线程数量不等于 CPU 核数，底层推理和编解码库也可能创建线程。

```text
Camera → Frame Pool → NPU 有界队列 → NPU 结果 → Main/Fusion
                   └→ DVR 输入队列 → RAM 时间环 → 编码任务
Radar → 雷达事件 ───────────────────────────→ Main/Fusion
Main/Fusion → 告警请求 + DVR 触发事件
编码任务 → 编码器 → MP4 临时文件 → 校验并提交到 TF
```

Camera 独占 V4L2 设备：等待就绪、DQBUF、检查帧、复制 MJPEG 至应用帧池、QBUF、发布不可变帧引用。异常分支同样处理缓冲归还和状态报告。队列或帧池耗尽时不长期占住驱动缓冲。

NPU 独占模型实例和 RGB 工作缓冲；解码后尽早释放 JPEG 引用。结果携带原始帧序号、采集时间和推理完成时间。Fusion 使用结果年龄判断其有效性，由同一个线程更新风险状态。

## Frame Pool、队列和 Ring

- **Frame Pool** 管理 MJPEG 存储与复用，设置帧容量、槽位数和总内存上限。启动时分配并检查结果；超大帧明确拒绝和计数，不截断 JPEG。
- **FrameRef** 用 RAII 管理共享生命周期；发布后帧数据只读，最后一个引用释放时回池。引用计数不替代队列同步，也不允许仍有消费者时复用帧。
- **NPU 队列** 有界，保留最近待处理帧，满时释放旧引用。抽帧间隔和结果最大年龄可配置。
- **DVR Ring** 保存按采集时间排序的 FrameRef，用时间窗口淘汰旧帧，同时受帧数和字节预算约束。目标为最近 15 秒，启动未满窗口时记录实际覆盖时长。
- **事件队列** 有界且可关闭。高频状态更新可以合并，录像触发和退出事件不能无声丢弃。满队列行为应在接口中明确。
- 第一版使用 `mutex + condition_variable`。锁内只更新容器或索引；帧析构/归还可能涉及另一把锁，批量取出引用后在锁外释放，避免锁顺序反转。

## 录像触发与后台编码

触发时，从 Ring 为事件窗口获取独立引用，随后收集到触发后 15 秒。Ring 淘汰自己的旧引用时，事件持有的帧仍有效。

事件收集和编码任务分别管理生命周期：编码上一段时继续维护预缓存。编码任务数、等待任务数和事件最长持续时间均有上限；相邻事件可在规定窗口内合并，超限要报告截断或拒绝原因。具体参数在内存预算内配置，不无限延长事件。

编码完成或失败必须释放任务的全部引用。等待、退出、异常和部分初始化失败的清理均需主机测试覆盖。

RAM 保存压缩后的 MJPEG，不为整个预录窗口缓存 RGB。内存上限应覆盖：滚动预缓存、被事件固定的帧、编码积压、NPU 工作区及其他运行内存。固定大小帧槽按槽位容量预算，不能只用平均 JPEG 大小。

例如，假设每帧有效数据为 100 KiB、25 FPS，15 秒 JPEG 数据约为 36.6 MiB，30 秒约为 73.2 MiB。这只是估算示例，实际分配还包含槽位余量与并行任务；不代表当前摄像头的测量值。池容量不能恰好只有 375 帧：环已占满时 Camera 仍需取得新槽位，事件和其他消费者也会固定帧。

RAM 预缓存避免持续写 TF，代价是进程退出或掉电时未提交的视频会丢失。正常退出可以在期限内排空任务，但不能承诺覆盖断电场景。

## 编码后端与时间戳

GStreamer `appsrc → JPEG 解码 → 格式转换 → H.264 编码 → MP4 封装` 是候选后端。STM32MP257 支持硬件编码，实际插件、输入格式和驱动能力仍需与目标 BSP 匹配。当前代码使用的编码 worker 与新后端通过独立接口衔接，方案文档不代表已完成后端替换。

如果将帧内存包装成 GstBuffer，必须通过释放回调持有 FrameRef 到下游真正释放；push 返回不等于消费者处理完成。设置流水线缓存上限，处理背压、错误和 EOS，收到封装完成结果后再提交文件。

优先保留驱动提供且时钟来源已确认的采集时间，同时记录本机接收时间；编码 PTS 相对片段起点生成。存在丢帧时按明确的时间戳策略处理，不能简单把所有帧强制视为等间隔而声称保持了原始时间线。

## 主机验收项

1. 多消费者持帧时不会提前复用，成功、失败和退出路径最终均归还帧。
2. 队列满时行为符合约定；队列关闭能唤醒空队列/满队列的等待者。
3. 触发前的帧被事件固定后，Ring 淘汰不破坏片段；编码时仍可收帧。
4. 重复触发、慢编码和内存不足时，内存及待处理任务均不超过配置上限。
5. 使用可控时钟验证窗口、结果过期、帧序号与 PTS，测试不依赖真实等待 30 秒。
6. 使用模拟采集与编码后端验证主流程，硬件吞吐、驱动与插件可用性留待板端确认。
