# STM32MP257 骑行辅助项目操作指南

本文只描述开发板上当前生效的 `camera_detect` 项目。默认环境：

```text
开发板管理地址：192.168.88.10
虚拟机板卡网口：192.168.88.150
虚拟机用户名：  alientek
板端程序目录：  /xxl/camera_detect
TF 卡挂载目录： /run/media/mmcblk0p1
```

IP 变化时先分别执行 `ip -br addr` 确认，不要照抄旧地址。

## 一、登录开发板

在虚拟机终端执行：

```bash
ssh root@192.168.88.10
```

退出开发板：

```bash
exit
```

## 二、日常启动、停止和重启

本项目由两个 systemd 单元管理：

- `dvr-m33.service`：早期启动 M33 固件；
- `dvr.service`：统一管理 `radar_fusion`、HUD、Dashboard 和 M33 回退。

常用命令：

```bash
# 启动主业务
systemctl start dvr.service

# 停止雷达、摄像头/NPU、DVR、HUD、Dashboard 和 M33
systemctl stop dvr.service

# 重启主业务
systemctl restart dvr.service

# 查看简要状态
systemctl is-active dvr.service dvr-m33.service

# 查看完整状态和进程树
systemctl status dvr.service dvr-m33.service --no-pager -l

# 设置开机启动
systemctl enable dvr.service dvr-m33.service

# 取消开机启动，但不立即停止
systemctl disable dvr.service dvr-m33.service
```

不要执行 `start_dvr.sh stop`：该脚本没有 `stop` 子命令，应由 systemd 发送退出
信号并执行完整清理。

## 三、确认功能是否真的在线

`dvr.service=active` 不能单独证明核心业务正常。至少检查：

```bash
systemctl is-active dvr.service dvr-m33.service
pgrep -a radar_fusion
test -e /dev/video7 && echo camera-ok
test -e /dev/ttySTM1 && echo radar-uart-ok
test -e /dev/ttyRPMSG0 && echo rpmsg-ok
cat /sys/class/remoteproc/remoteproc0/state
curl -s http://127.0.0.1:8080/api/state
```

Dashboard JSON 中应看到：

```json
"stale": false
```

手机或电脑连接开发板 WiFi 后访问：

```text
http://<开发板WiFi地址>:8080
```

查看开发板全部地址：

```bash
ip -br addr
```

## 四、查看日志

### 1. 业务完整日志

```bash
tail -n 200 /xxl/camera_detect/dvr_system.log
tail -f /xxl/camera_detect/dvr_system.log
```

内容包括：

- M33、RPMsg、雷达串口和摄像头初始化；
- NPU 推理、目标出现/消失和融合告警；
- DVR 缓存、触发、编码和 MP4 保存；
- IMU/V2X 事件及 A35 向 HUD 转发；
- 导航/OLED、音频和程序退出原因。

### 2. Dashboard 访问日志

```bash
tail -f /xxl/camera_detect/radar_dashboard.log
```

内容包括 Dashboard 启动地址、浏览器/API 请求和 HTTP 错误。

### 3. HUD 与手机转发日志

```bash
tail -f /tmp/hud.log
```

内容包括：

- HUD 接收到的 M33/IMU 事件；
- 向手机 UDP 广播的 JSON；
- 网络不可达等发送错误；
- OLED 和导航端口状态。

该文件在 tmpfs 中，重启后消失，不写 TF 卡。

### 4. systemd 日志

```bash
journalctl -b -u dvr.service --no-pager
journalctl -b -u dvr-m33.service --no-pager
journalctl -f -u dvr.service
```

适合分析开机顺序、异常退出和 systemd 自动重启。查看自动重启次数：

```bash
systemctl show dvr.service -p NRestarts -p MainPID
```

## 五、TF 卡数据与实验日志

```text
/run/media/mmcblk0p1/dvr/
├── emergency_*.mp4                 # 正式事件录像
├── .buffer/                        # 当前仍在 TF 的临时 DVR 缓存
└── radar_experiments/
    ├── radar_data.csv              # 每个雷达 objId 的距离/速度/角度/TTC
    ├── radar_state.json            # Dashboard 当前状态快照
    ├── sensor_events.csv           # 摄像头/NPU、雷达、IMU 同步事件
    ├── imu_delivery.csv            # M33→A35→HUD→手机投递过程
    └── labels.csv                  # 网页人工开始/结束标注
```

轮转规则：

| 文件 | 单文件上限 | 历史份数 |
|---|---:|---:|
| `dvr_system.log` | 10 MiB | 3 |
| `radar_dashboard.log` | 5 MiB | 3 |
| `/tmp/hud.log` | 5 MiB | 2 |
| `radar_data.csv` | 20 MiB | 4 |
| `sensor_events.csv` | 20 MiB | 4 |
| `imu_delivery.csv` | 10 MiB | 4 |

CSV 历史文件后缀为 `.1` 到 `.4`，`.1` 最新。`labels.csv` 属于人工标定成果，
不自动清理；MP4 也不会被日志轮转删除。

## 六、从开发板复制视频到虚拟机

### 推荐：在虚拟机主动拉取

先在虚拟机创建保存目录：

```bash
mkdir -p /home/alientek/Videos/stm32mp257
```

复制一个指定视频：

```bash
scp 'root@192.168.88.10:/run/media/mmcblk0p1/dvr/emergency_20260721_170823.mp4' \
  /home/alientek/Videos/stm32mp257/
```

复制 TF 卡 DVR 根目录下全部 MP4：

```bash
scp 'root@192.168.88.10:/run/media/mmcblk0p1/dvr/*.mp4' \
  /home/alientek/Videos/stm32mp257/
```

文件名含中文或空格时，保持远端路径带引号，或者先执行：

```bash
ssh root@192.168.88.10 'ls -lh /run/media/mmcblk0p1/dvr/*.mp4'
```

再复制准确文件名。

### 从开发板主动推送

先在虚拟机创建目录，然后登录开发板执行：

```bash
scp '/run/media/mmcblk0p1/dvr/emergency_20260721_170823.mp4' \
  alientek@192.168.88.150:/home/alientek/Videos/stm32mp257/
```

出现密码提示时输入虚拟机登录密码。不要把密码写进命令、脚本、Shell 历史或
Git 仓库。

复制后校验：

```bash
# 开发板
sha256sum '/run/media/mmcblk0p1/dvr/emergency_20260721_170823.mp4'

# 虚拟机
sha256sum '/home/alientek/Videos/stm32mp257/emergency_20260721_170823.mp4'
```

两个哈希一致才说明传输完整。

## 七、安全清除项目历史日志

执行：

```bash
/xxl/camera_detect/scripts/clear_runtime_logs.sh
```

脚本会：

1. 记录 `dvr.service` 原状态；
2. 停止业务，避免截断正在写入的 CSV；
3. 删除项目文本日志、雷达/传感器/IMU CSV 及轮转文件；
4. 删除旧 `radar_state.json`；
5. 保留正式 MP4、`labels.csv` 和 systemd journal；
6. 如果业务原来正在运行，自动重新启动并生成带表头的新 CSV。

清理后验证：

```bash
systemctl is-active dvr.service
pgrep -a radar_fusion
curl -s http://127.0.0.1:8080/api/state
head -1 /run/media/mmcblk0p1/dvr/radar_experiments/radar_data.csv
head -1 /run/media/mmcblk0p1/dvr/radar_experiments/sensor_events.csv
head -1 /run/media/mmcblk0p1/dvr/radar_experiments/imu_delivery.csv
```

## 八、安全拔出 TF 卡

```bash
systemctl stop dvr.service
sync
umount /run/media/mmcblk0p1
```

确认已卸载：

```bash
findmnt /run/media/mmcblk0p1
```

无输出后再拔卡。重新插卡后由系统自动检查和挂载；不要在 fsck 运行时手工挂载。

## 九、编译和部署

在虚拟机执行：

```bash
cd /home/alientek/dvr_project/mier/lyr/camera_detect
make
make deploy-radar BOARD_IP=192.168.88.10
```

部署后：

```bash
ssh root@192.168.88.10 'systemctl restart dvr.service'
```

启动优化配置不是日常命令，只在明确需要时执行：

```bash
/xxl/camera_detect/scripts/boot_optimize.sh apply
/xxl/camera_detect/scripts/boot_optimize.sh rollback
```

执行 `apply` 或 `rollback` 后需要重启开发板并重新完成全部功能验收。
