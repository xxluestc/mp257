# 跨电脑编译、部署与烧录交接

本文用于在另一台电脑从GitHub重新取得当前工程，并复现A35编译、MP257部署和WBA
烧录。不要复制虚拟机中的旧二进制或旧工程目录，以远端`master`为唯一代码基线。

## 1. 仓库和工程边界

远端仓库：

```text
https://github.com/xxluestc/mp257.git
```

仓库维护三部分：

```text
mier/lyr/camera_detect/       MP257 A35 Linux主业务，本机交叉编译后通过SSH部署
E04-2G4M10S1AX/              WBA方向灯终端，使用Keil下载
V2V_keil/E04-2G4M10S1AX/    V2V语音终端，使用Keil下载
```

MP257 A35程序不是通过ST-Link“烧录”，而是交叉编译后用SCP部署到
`/xxl/camera_detect`。WBA工程才使用Keil和ST-Link下载。MP257 M33完整SDK不在本仓库
维护范围内，板上现有M33固件保持不变；本次TF录像修改不需要重烧M33、U-Boot、内核
或DTB。

## 2. 当前MP257功能清单

当前整机软件覆盖以下功能，换电脑时可据此逐项验收：

| 功能域 | 当前实现 |
|---|---|
| 雷达 | AT6010多目标解析，保留objId/距离/速度/角度/TTC，危险目标选择，LEFT/CENTER/RIGHT可配置阈值和方向滤波 |
| 视觉融合 | USB摄像头MJPEG采集、STM32MP2 NPU目标检测，以既有规则确认雷达碰撞风险 |
| 本机告警 | PD11告警灯、碰撞/摔倒音频；录像失败不得改变风险判断和告警状态 |
| 蓝牙方向灯 | MP257 USART2连接CH9140，向WBA发送`RISK LEFT/RIGHT/CENTER/CLEAR`并接收ACK |
| 摔倒与V2X | M33通过RPMsg上报IMU摔倒和V2X事件；A35负责告警、HUD/UDP投递和同步日志 |
| HUD/手机协同 | OLED/HUD显示，手机UDP通信、导航消息和本地TTS缓存；短信最终发送仍由手机App完成 |
| DVR | 风险/摔倒事件前后视频、连续事件窗口合并、异步H.264/MP4编码、整段解码校验、fsync和原子提交到TF |
| 数据记录 | 雷达CSV、跨传感器事件CSV、IMU投递CSV、人工`labels.csv`及容量轮转 |
| Dashboard | 8080实时雷达扇形图/曲线、传感器同步、彩色风险与录像日志、服务状态、标注、TF和安全启停 |
| OTA | 独立8090服务，A35版本上传、校验、切换、健康检查和失败回滚；不升级M33/内核/DTB |
| 启动运维 | M33独立早启、A35 systemd服务、日志维护、TF识别/安全弹出、项目安全启停和有序关机 |

`make deploy-runtime`可以完整复现仓库内的A35应用运行态：二进制、STAI库、模型、
声音、Dashboard、脚本和三个systemd unit都会部署，现场`radar_config`保留。以下属于
板级前提或独立设备，不由该命令改写：

- MP257系统镜像、内核、当前DTB和设备节点；
- 板上M33固件本体及`/home/root/project/fw_cortex_m33.sh`；
- 板端`python3`、FFmpeg/ffprobe、ALSA等系统包；
- WBA方向灯固件和V2V语音终端固件（分别用Keil/ST-Link烧录）；
- 稳定目录`/opt/helmet-ota`中的OTA服务，首次换板需另执行`make deploy-ota-service`。

因此“换电脑”可以从GitHub完整重建并部署A35当前版本；“换一块全新的开发板”还必须
先准备匹配的Linux BSP/DTB、M33固件和系统依赖，不能把应用部署误认为整机刷机。

## 3. 新Linux电脑准备

```bash
aarch64-linux-gnu-gcc --version

python3 --version
git --version
```

## 4. 拉取并确认唯一最新状态

```bash
git clone https://github.com/xxluestc/mp257.git
cd mp257
git switch master
git pull --ff-only origin master
git status --short --branch
git log -1 --oneline
```

`git status`应显示`master...origin/master`且没有修改。不要从聊天附件、旧OTA解包目录
或U盘覆盖源码。需要确认本次TF修复已经存在时：

```bash
grep -n 'TF 录像主存储已就绪' mier/lyr/camera_detect/start_dvr.sh
grep -n 'dvr-mount-dir' mier/lyr/camera_detect/radar_fusion.cpp
```

## 5. 从零编译A35应用

```bash
cd mier/lyr/camera_detect
make clean
make -j"$(nproc)"
```

该命令会：

1. 交叉编译`radar_fusion`；
2. 交叉编译`hud_project/hud`；
3. 检查Dashboard Python、DVR编码worker和所有Shell脚本；
4. 执行Dashboard单元测试。

检查产物架构：

```bash
file radar_fusion hud_project/hud
```

两者都应显示`ARM aarch64`。仓库已包含构建所需源码、AArch64 STAI动态库及头文件、
NPU模型、音频和网页资源；构建产物被`.gitignore`排除，因此换电脑必须重新执行
`make`，不依赖旧电脑残留文件。

## 6. 部署到MP257

前提：开发板可通过`root@192.168.88.10`访问，TF卡已经插入。

```bash
make deploy-runtime BOARD_IP=192.168.88.10 BOARD_DIR=/xxl/camera_detect
```

该目标会复制主程序、HUD、AArch64 STAI动态库、模型、声音、Dashboard、TF/DVR脚本
和服务示例，安装`dvr-m33`、Dashboard与主业务unit并重启A35业务；不会覆盖现场
`radar_config`，也不会重启已经运行的M33。只复制文件而不重启时使用`make deploy-radar`。

首次部署本次服务配置，或确认板上仍使用旧的150秒停止超时时：

```bash
ssh root@192.168.88.10 '
  cp /xxl/camera_detect/dvr.service.example /etc/systemd/system/dvr.service &&
  cp /xxl/camera_detect/dvr-m33.service.example /etc/systemd/system/dvr-m33.service &&
  cp /xxl/camera_detect/radar-dashboard.service.example \
     /etc/systemd/system/radar-dashboard.service &&
  systemctl daemon-reload &&
  systemctl enable dvr-m33.service radar-dashboard.service dvr.service &&
  systemctl restart radar-dashboard.service dvr.service
'
```

检查服务与TF主存储：

```bash
ssh root@192.168.88.10 '
  systemctl is-active dvr.service radar-dashboard.service
  systemctl show dvr.service -p TimeoutStopUSec
  /xxl/camera_detect/scripts/tf_card_control.sh status
  grep -E "TF 录像主存储|DVR录像存储|TF storage attached" \
    /xxl/camera_detect/dvr_system.log | tail -20
'
```

预期：TF状态为`mounted`，日志显示实际`<挂载点>/dvr`。TF缺失、不可挂载或不可写时
`dvr.service`仍保持雷达/LED告警运行，录像被禁用并在日志和Dashboard明确标红；程序
绝不把视频回退写入板载根文件系统。

## 7. 录像验收

真实雷达+NPU风险或真实摔倒触发后，至少等待最后一次风险结束15秒，并继续等待日志
出现`DVR-WORKER VALIDATED`：

```bash
ssh root@192.168.88.10 '
  grep -E "Save triggered|DVR-WORKER|Encoder finished|State reset" \
    /xxl/camera_detect/dvr_system.log | tail -100
  /xxl/camera_detect/scripts/verify_dvr_videos.sh --full
'
```

查看实际录像目录：

```bash
ssh root@192.168.88.10 '
  mount=$(/xxl/camera_detect/scripts/tf_card_control.sh status |
    sed -n "s/.* mount=\([^ ]*\).*/\1/p")
  ls -lht "$mount/dvr"
'
```

只有`.mp4`且整段解码通过才算成功；`.part`和`.buffer.failed_*`都需要继续排查。

## 8. 安全弹出和重新启动

Dashboard的“安全弹出TF”会先停止业务并等待编码，再同步和卸载。命令行：

```bash
ssh root@192.168.88.10 '
  /xxl/camera_detect/scripts/project_safe_stop.sh stop &&
  /xxl/camera_detect/scripts/tf_card_control.sh eject
'
```

重新插入后：

```bash
ssh root@192.168.88.10 '
  /xxl/camera_detect/scripts/tf_card_control.sh mount &&
  systemctl start dvr.service
'
```

禁止在`dvr.service`运行中直接卸载或物理拔卡。

## 9. WBA Keil编译和ST-Link烧录

方向灯终端：

```text
E04-2G4M10S1AX/MDK-ARM/02_test.uvprojx
```

V2V语音终端：

```text
V2V_keil/E04-2G4M10S1AX/MDK-ARM/02_test.uvprojx
```

Windows电脑安装Keil MDK和对应STM32WBA Device Pack，打开正确的`uvprojx`后执行
Rebuild，再通过ST-Link下载。两个工程用途不同，不能相互覆盖。具体CH9140协议、LED
引脚和联调命令见`docs/BLUETOOTH_DIRECTION_LED.md`；V2V语音逻辑见
`docs/PROJECT_TECHNICAL_KNOWLEDGE_BASE.md`的V2V章节。

## 10. 提交和发布检查清单

```bash
git status --short
git diff --check
make clean
make -j"$(nproc)"
make ota-check
git status --short
```

发布前必须在真实MP257上补做：TF自动识别、写入探测、雷达触发、摔倒触发、连续
LEFT/CENTER/RIGHT、间隔两次触发、安全停止中编码、安全弹出、重挂后整段解码和
SHA-256复核。主机编译通过不能替代真实TF和摄像头链路验证。
