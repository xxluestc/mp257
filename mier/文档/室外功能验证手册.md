# 室外功能验证手册

> 适用对象：基于 STM32MP257 的电动车主动安全骑行辅助系统  
> 验证场景：室外道路/场地实测  
> 验证目标：确认雷达+摄像头 TTC 触发、IMU 摔倒触发、V2X 方向语音告警三个核心功能可正常工作。

---

## 一、验证前准备

### 1.1 硬件连接检查

| 项目 | 要求 | 检查命令 |
|---|---|---|
| 摄像头 | 连接至 `/dev/video7` | `ls -la /dev/video7` |
| 毫米波雷达 | 连接至 `/dev/ttySTM1` | `ls -la /dev/ttySTM1` |
| TF 卡 | 挂载到 `/run/media/mmcblk0p1` | `df -h /run/media/mmcblk0p1` |
| MAX98357A 功放 | 已使能，骨传导耳机接入 | `aplay -l` |
| LED | PD11 可用 | 运行中观察是否闪烁 |
| M33 固件 | 启动后 `/dev/ttyRPMSG0` 出现 | `ls -la /dev/ttyRPMSG0` |

### 1.2 软件与文件检查

登录开发板：

```bash
ssh root@192.168.88.10
cd /xxl/camera_detect
ls -la
ls -la sounds/
```

确认存在：
- `radar_fusion`（可执行）
- `start_dvr.sh`（可执行）
- `sounds/fall_alert.wav`
- `sounds/collision_alert.wav`
- `sounds/v2x_*.wav`（5 个方向音频）

### 1.3 清理旧视频

```bash
ssh root@192.168.88.10 'rm -f /run/media/mmcblk0p1/dvr/emergency_*.mp4'
```

## 二、启动系统

### 2.1 一键启动

```bash
ssh root@192.168.88.10
cd /xxl/camera_detect
./start_dvr.sh
```

启动后终端只显示关键事件，完整日志写入 `/xxl/camera_detect/dvr_system.log`。

### 2.2 启动参数（根据现场调整）

```bash
# 默认：TTC 2.5s，距离 3m
./start_dvr.sh

# 若后方电动车靠近较慢，可调低灵敏度 (H合适)
./start_dvr.sh -T 1.5 -D 2

# 若太灵敏，要求更近/更紧急才触发
./start_dvr.sh -T 4.0 -D 4
```

### 2.3 启动成功标志

终端应出现：

```text
[关键] [DVR] ffmpeg: OK
[关键] [DVR] TF card: OK (/run/media/mmcblk0p1/dvr)
[关键] [FUSION] Camera + NPU enabled
[关键] [IMU] RPMsg ready message sent to M33
```

> 如果看到 `[FUSION] Camera not available, radar-only mode`，说明摄像头未识别，需检查 `/dev/video7` 或重新插拔摄像头。

## 三、功能一：雷达 + 摄像头 TTC 触发 DVR

### 3.1 验证方法

1. 启动系统后，让一人骑自行车/电动车从后方靠近。
2. 被测车辆保持静止或低速。
3. 后方目标进入雷达检测范围（建议 5m 内），并持续靠近。

### 3.2 预期终端打印

```text
[关键] [   1.2s] NPU: ROAD USER DETECTED (person 0.92)
[关键] [DVR] Recording started (buffer: /run/media/mmcblk0p1/dvr/.buffer)
[关键] [   2.5s] *** NPU CONFIRMED: Real road user! ***
[关键] [   3.1s] RADAR: 1 targets, dist=3m, TTC=2.0s, alert=YES
[关键]   >>> ALERT: COLLISION RISK - NPU CONFIRMED <<<
[关键] [AUDIO] Playing collision alert
[关键] [DVR] Save triggered! (pre=15s, post=15s)
[关键] [DVR] Post-trigger recording complete (15012 ms)
[保存] [DVR] Child: Saved /run/media/mmcblk0p1/dvr/emergency_20260623_123456.mp4
[关键] [DVR] Encoder finished (exit=0)
[关键] [DVR] State reset, ready for next trigger
```

### 3.3 关键观察点

- LED 是否闪烁
- 是否播放碰撞提示音
- 是否生成 `emergency_*.mp4`
- 视频时长是否约为 30 秒（15s 前 + 15s 后）

### 3.4 事后验证

```bash
ssh root@192.168.88.10 'ls -lh /run/media/mmcblk0p1/dvr/emergency_*.mp4 && ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1 /run/media/mmcblk0p1/dvr/emergency_*.mp4'
```

拷贝到本地查看：

```bash
scp root@192.168.88.10:/run/media/mmcblk0p1/dvr/emergency_*.mp4 ~/dvr_videos/
```

## 四、功能二：IMU 摔倒触发 DVR

### 4.1 验证方法

**方法 A：模拟测试（推荐出门前快速验证）**

```bash
ssh root@192.168.88.10 'cd /xxl/camera_detect && ./start_dvr.sh -t 10'
```

启动 10 秒后自动模拟摔倒，无需真的摔倒。

**方法 B：真实摔倒测试（室外）**

1. 启动系统：`./start_dvr.sh`
2. 骑行/推行车辆，模拟摔倒动作（注意安全，建议低速侧倾）。
3. M33 检测到摔倒后通过 RPMsg 通知 A35。

### 4.2 预期终端打印

```text
[关键] [TEST] Simulating IMU fall after 10 seconds...
[关键] [TEST] Injecting simulated FALL event
[关键] [IMU] *** FALL DETECTED! *** Triggering emergency save
[关键] [AUDIO] Playing fall alert
[关键] [DVR] Fall-triggered recording started (no pre-buffer)
[关键] [DVR] Save triggered! (pre=15s, post=15s)
[关键] [DVR] Post-trigger recording complete (15005 ms)
[保存] [DVR] Child: Saved /run/media/mmcblk0p1/dvr/emergency_20260623_123501.mp4
[关键] [DVR] Encoder finished (exit=0)
```

### 4.3 两种情况

| 场景 | 视频时长 | 说明 |
|---|---|---|
| 摔倒前已有目标缓冲 ≥15s | 约 30s | 15s 前 + 15s 后 |
| 摔倒前无目标缓冲 | 约 15s | 从摔倒瞬间开始录制 15s |
| 摔倒前缓冲不足 15s | 15s ~ 30s | 实际缓冲长度 + 15s 后录 |

### 4.4 事后验证

同 3.4，检查视频时长与文件。

## 五、功能三：V2X 方向语音告警

### 5.1 验证方法

**条件**：需要有另一台带 V2X 终端（蓝牙广播）的车辆/设备靠近。

1. 启动系统：`./start_dvr.sh`
2. 让另一台 V2X 设备从**不同方向**靠近（左前、右前、左侧、右侧、后方附近）。
3. M33 解析蓝牙广播后，会通过 RPMsg 发送 `V2X_ALERT`。

### 5.2 预期终端打印

```text
[关键] [V2X] V2X_ALERT seq=1 direction=left_front warning=左前方有来车，请注意
[关键] [AUDIO] Playing V2X alert: left_front
```

### 5.3 方向与语音对应关系

| direction | 播放内容 | 音频文件 |
|---|---|---|
| `nearby` | 附近有来车，请注意观察 | `v2x_nearby.wav` |
| `left_front` | 左前方有来车，请注意 | `v2x_left_front.wav` |
| `right_front` | 右前方有来车，请注意 | `v2x_right_front.wav` |
| `left` | 左侧有来车，请注意 | `v2x_left.wav` |
| `right` | 右侧有来车，请注意 | `v2x_right.wav` |

### 5.4 无 V2X 设备时的替代验证

若现场没有另一台 V2X 设备，至少验证音频通路：

```bash
ssh root@192.168.88.10
aplay /xxl/camera_detect/sounds/v2x_left_front.wav
aplay /xxl/camera_detect/sounds/v2x_right.wav
```

应能从骨传导耳机听到清晰中文提示。

## 八、常见问题速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 摄像头未识别 | `/dev/video7` 不存在或被占用 | 检查连接，执行 `fuser -k /dev/video7` |
| 没有声音 | 音频文件缺失或声卡未识别 | `ls sounds/`，`aplay -l` |
| 没有生成 MP4 | TF 卡未挂载或 ffmpeg 缺失 | `df -h /run/media/mmcblk0p1`，`which ffmpeg` |
| V2X 无告警 | 无其他 V2X 设备或 M33 固件异常 | 检查 `/dev/ttyRPMSG0`，运行 `a35_read_v2x_alerts.sh` |
| LED 不亮 | GPIO 被占用 | 检查是否有其他程序占用 `/dev/gpiochip3` line 11 |
| `Ctrl+C` 卡住 | 旧版脚本 | 确认 `start_dvr.sh` 已更新到最新版 |

## 十、蓝牙串口终端（手机 APP 远程控制）

系统新增 `/xxl/camera_detect/bt_shell.sh`，通过 CH9141 蓝牙串口透传模块（`/dev/ttySTM0`）与手机 APP 通信。

### 10.1 功能

- **实时日志**：`start_dvr.sh` 运行期间，关键事件会自动转发到手机蓝牙 APP。
- **远程控制**：手机 APP 可发送命令启停 DVR、查询状态、查看日志、执行 shell 命令。
- **串口终端效果**：手机 APP 发送的命令会由开发板执行并返回结果。

### 10.2 启动蓝牙终端

开发板上电后，蓝牙终端会自动运行（若已加入启动脚本）；或手动启动：

```bash
ssh root@192.168.88.10
cd /xxl/camera_detect
nohup ./bt_shell.sh > /tmp/bt_shell_nohup.log 2>&1 </dev/null &
```

启动成功后，手机连接蓝牙模块，APP 会立即收到欢迎信息：

```text
========== DVR 蓝牙串口终端 ==========
可用命令：
  start            启动 DVR 系统
  stop             停止 DVR 系统
  restart          重启 DVR 系统
  status           查询运行状态
  log [N]          输出最近 N 行日志（默认 20）
  exec <命令>      执行任意 shell 命令并返回结果
  ls               列出已保存的紧急视频
  clear            清空 DVR 日志文件
  help             显示本帮助
======================================
[2026-07-01 16:25:19] 状态: DVR 未运行
```

### 10.3 手机 APP 操作

使用手机端的蓝牙串口 APP（如沁恒官方蓝牙串口助手、nRF Connect、LightBlue）：

1. 打开手机蓝牙，连接名称为 `WCH MODULE`（或你修改后的名称）的设备。
2. 进入透传服务 `0xFFF0`。
3. 开启 `0xFFF1` 通知，用于接收开发板发送的数据。
4. 向 `0xFFF2` 写入命令。

### 10.4 常用命令

| 命令 | 功能 | 示例 |
|---|---|---|
| `start` | 启动 DVR 系统 | `start` |
| `stop` | 停止 DVR 系统 | `stop` |
| `restart` | 重启 DVR 系统 | `restart` |
| `status` | 查询运行状态 | `status` |
| `log 30` | 输出最近 30 行日志 | `log 30` |
| `ls` | 列出已保存的紧急视频 | `ls` |
| `exec <命令>` | 执行任意 shell 命令 | `exec ls -l /run/media/mmcblk0p1/dvr/` |
| `clear` | 清空日志文件 | `clear` |
| `help` | 显示帮助 | `help` |

### 10.5 典型使用流程

1. 手机连接蓝牙模块。
2. APP 收到欢迎信息后，发送 `start`。
3. 开发板启动 DVR，手机开始收到 `[DVR]` 关键日志：
   ```text
   [DVR] [关键] [DVR] 雷达 TTC 阈值: 2.5 s
   [DVR] [关键] [FUSION] Camera + NPU enabled
   [DVR] [关键] [IMU] RPMsg ready message sent to M33
   ```
4. 触发雷达告警或 IMU 摔倒后，手机会收到：
   ```text
   [DVR] [关键]   >>> ALERT: COLLISION RISK - NPU CONFIRMED <<<
   [DVR] [保存] [DVR] Child: Saved /run/media/mmcblk0p1/dvr/emergency_xxx.mp4
   ```
5. 需要停止时，手机发送 `stop`。

### 10.6 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| APP 收不到欢迎信息 | 蓝牙未连接透传服务 | 确认连接了 `0xFFF0` 服务并开启了 `0xFFF1` 通知 |
| 发送命令无响应 | 未向 `0xFFF2` 写入 | 确认写入的是 `0xFFF2` 特征值 |
| 日志有乱码 | 波特率不匹配 | 确认 CH9141 波特率为 115200 |
| 启动 DVR 后无日志 | `start_dvr.sh` 蓝牙转发失败 | 检查 `/dev/ttySTM0` 是否存在，手动运行 `start_dvr.sh` 查看打印 |
