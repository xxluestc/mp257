# 开机自启动配置教程

米尔 MYD-LD25X 的 A35 Linux 使用 **systemd** 作为初始化系统。要把脚本设置为开机自启动，最规范、最可靠的方式是给每个脚本写一个 **systemd service 单元文件**，然后启用它。

本教程包含两个示例：

1. DVR 启动脚本：`/xxl/camera_detect/start_dvr.sh`
2. 队友 HUD 脚本：`/root/hud`（若实际路径不同，请替换）

---

## 一、基本思路

- `start_dvr.sh` 和 `/root/hud` 都只是普通脚本。
- 要让它们在开机时自动运行，需要额外告诉 systemd：**“开机到多用户模式后，帮我执行这个脚本，并在崩溃时自动重启。”**
- 每个脚本对应一个 `.service` 文件，彼此独立，方便单独控制、单独看日志。

---

## 二、给 DVR 脚本创建服务

### 1. 创建服务文件

在开发板上新建文件：

```text
/etc/systemd/system/dvr-startup.service
```

内容如下：

```ini
[Unit]
Description=DVR Radar Fusion Startup
After=network.target systemd-udevd.service systemd-modules-load.service
# 如果 DVR 必须依赖 TF 卡，取消下面这行注释
# RequiresMountsFor=/run/media/mmcblk0p1

[Service]
Type=simple
User=root
WorkingDirectory=/xxl/camera_detect
ExecStart=/xxl/camera_detect/start_dvr.sh
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

说明：

- `Type=simple`：systemd 认为主进程就是 `start_dvr.sh` 本身。
- `User=root`：脚本需要操作 GPIO、摄像头、串口、加载 M33 固件，必须用 root。
- `WorkingDirectory`：脚本内部使用相对路径，需要进入 `/xxl/camera_detect`。
- `Restart=on-failure`：脚本异常退出后 5 秒自动重启。

### 2. 启用并测试

```bash
systemctl daemon-reload
systemctl enable dvr-startup.service
systemctl start dvr-startup.service
systemctl status dvr-startup.service
```

重启开发板验证：

```bash
reboot
```

重启后检查：

```bash
systemctl status dvr-startup.service
```

## 三、给队友 HUD 脚本创建服务

假设队友脚本在 root 用户主目录下，绝对路径为 `/root/hud`，并且该脚本本身有执行权限、第一行是 `#!/bin/sh` 或 `#!/bin/bash`。

### 1. 创建服务文件

```text
/etc/systemd/system/hud-startup.service
```

内容：

```ini
[Unit]
Description=HUD Startup Script
After=network.target
# 如果 HUD 需要等 DVR 启动完再启动，加上下面两行
# After=dvr-startup.service
# Requires=dvr-startup.service

[Service]
Type=simple
User=root
WorkingDirectory=/root
ExecStart=/root/hud
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
```

### 2. 启用并测试

```bash
systemctl daemon-reload
systemctl enable hud-startup.service
systemctl start hud-startup.service
systemctl status hud-startup.service
```

## 四、常用管理命令

| 操作 | 命令 |
|------|------|
| 查看服务状态 | `systemctl status dvr-startup.service` |
| 启动服务 | `systemctl start dvr-startup.service` |
| 停止服务 | `systemctl stop dvr-startup.service` |
| 重启服务 | `systemctl restart dvr-startup.service` |
| 关闭开机自启 | `systemctl disable dvr-startup.service` |
| 查看开机是否启用 | `systemctl is-enabled dvr-startup.service` |

## 五、查看日志

`start_dvr.sh` 默认把日志写进：

```text
/xxl/camera_detect/dvr_system.log
```

可以用：

```bash
tail -f /xxl/camera_detect/dvr_system.log
```

如果想让脚本输出进入 systemd 的 journal，便于用 `journalctl` 统一管理，可以在服务文件 `[Service]` 段加：

```ini
StandardOutput=journal
StandardError=journal
```

然后查看：

```bash
journalctl -u dvr-startup.service -f
```

> 注意：因为 `start_dvr.sh` 内部已经写了 `>> dvr_system.log`，即使开了 `StandardOutput=journal`，它的 `log()` 输出仍会同时进入自己的日志文件。要完全走 journal，需要修改脚本去掉 `>> "$LOG_FILE"`。

## 六、自启动后如何在串口终端看到调试信息

### 情况 1：开机后已经在串口终端前

直接用 `tail` 跟踪日志文件：

```bash
tail -f /xxl/camera_detect/dvr_system.log
```

这个文件里有 `[目标]`、`[告警]`、`[保存]`、`[系统]` 等全部运行日志，和手动运行 `./start_dvr.sh` 时看到的**关键内容一致**，只是没有颜色。

### 情况 2：使用 journal

如果在 service 文件里开了 `StandardOutput=journal`，则用：

```bash
journalctl -u dvr-startup.service -f
```

### 情况 3：想保留“手动运行时的彩色实时输出”

那就不需要把 `start_dvr.sh` 做成开机服务。可以把它放到登录 shell 的启动脚本里，例如 `/etc/profile.d/dvr.sh`：

```bash
#!/bin/sh
/xxl/camera_detect/start_dvr.sh &
```

这样每次通过串口登录时，它会自动在后台启动，并且你当前终端仍能看到彩色输出。但缺点是：

- 不是真正“开机即启动”，而是“登录后才启动”；
- 退出登录后服务可能停止（取决于 `nohup` 等处理）。

**最推荐的方式还是 systemd service + `tail -f` 看日志。**

## 七、常见问题

### 1. 服务启动失败，提示找不到设备

DVR 依赖 `/dev/video7`、 `/dev/ttySTM1`、 `/dev/ttyRPMSG0` 等设备。如果服务启动时这些设备还没准备好，可以在 `[Unit]` 里加：

```ini
After=systemd-udevd.service dev-video7.device dev-ttySTM1.device
```

其中 `dev-video7.device` 等设备单元由 systemd 根据 `/dev` 节点自动生成。

### 2. TF 卡没插导致服务失败

如果脚本检测到 TF 卡不存在时会退出，并且你希望在插卡后再启动，可以使用：

```ini
[Unit]
RequiresMountsFor=/run/media/mmcblk0p1
```

或者去掉 `RequiresMountsFor`，让脚本自己处理无卡情况。

### 3. 脚本没有执行权限

确保脚本可执行：

```bash
chmod +x /xxl/camera_detect/start_dvr.sh
chmod +x /root/hud
```

### 4. 想临时禁止某个服务开机自启

```bash
systemctl disable dvr-startup.service
```

再次启用：

```bash
systemctl enable dvr-startup.service
```

---

## 七、替代方案：/etc/rc.local

如果你不想写 systemd service，也可以编辑 `/etc/rc.local`，在 `exit 0` 之前加：

```bash
/xxl/camera_detect/start_dvr.sh &
/root/hud &
```

但这种方式：

- 脚本崩溃不会自动重启；
- 日志分散，不好排查；
- 依赖顺序不好控制。

**仍然推荐使用 systemd service。**
